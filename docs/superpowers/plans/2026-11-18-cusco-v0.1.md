# Cusco v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Cusco v0.1 service, hook command and CLI so that `cusco watch --json` shows live, correctly derived state for Claude Code and Codex sessions.

**Architecture:** One Rust crate with a library and one binary, `cusco`. A single core thread owns the node tree, the client adapters and the subscriber list. Other threads only move bytes: the ingest socket reader, the API listener and one writer per connection, and one exit watcher per tracked process. They all feed the core through a `std::sync::mpsc` channel. The core sleeps on that channel with a timeout equal to the next staleness deadline, so there's no polling loop.

**Tech Stack:** Rust (edition 2024, installed toolchain 1.91), `serde`, `serde_json`, `sha2`, `humantime`, `libc`. macOS only.

**Spec:** `docs/design.md`

## Global Constraints

- Dependencies are limited to `serde` (derive), `serde_json`, `sha2`, `humantime` and `libc`. No async runtime, no CLI-parsing crate, no test-only crates. Do not enable `serde_json`'s `preserve_order` feature, because the tool-input digest relies on sorted keys.
- macOS only. Process functions use `libc::proc_pidpath`, `libc::proc_pidinfo` (`PROC_PIDTBSDINFO`), `libc::proc_listallpids` and `kqueue` with `EVFILT_PROC`/`NOTE_EXIT`.
- The hook command never writes to stdout, always exits 0, and never blocks on Cusco. Claude Code reads hook stdout on some events, so any output would change agent behavior.
- Prompts, responses, commands and tool arguments never cross the ingest socket or touch disk. Only the allowed fields in `HookRecord` do.
- The socket directory is `$CUSCO_DIR` if set, otherwise `~/Library/Application Support/cusco`, created with mode `0700`. Socket names: `ingest.sock` and `api.sock`. Unix socket paths must stay under 104 bytes. Tests use short directories under `/tmp`.
- Wire protocol: version `1`, one UTF-8 JSON object per line. Timestamps on the wire are RFC 3339 with milliseconds and a `Z` suffix, produced by `humantime::format_rfc3339_millis`.
- `STALE_AFTER = 3_600_000` ms. `SUBSCRIBER_QUEUE = 256` lines.
- Ids taken from hook payloads are at most 128 bytes and contain no `/`.
- Commit messages carry no AI attribution: no `Co-Authored-By` trailer and no "Generated with" line.

## Review Focus

1. **Out-of-order hook delivery.** Claude and Codex run hooks concurrently, so a `SubagentStart` or `PostToolUse` can arrive after the `Stop` or `SessionEnd` it preceded. A late record must never reopen a closed turn or session and leave it `working`. *Test: Task 5, `late_events_do_not_reopen`.*
2. **Malformed ids.** A session or tool id containing `/` or longer than 128 bytes would corrupt node paths. The record must be rejected and nothing should change. *Test: Task 4, `ids_with_slash_or_too_long_are_rejected`.*
3. **Oversized records.** macOS caps local datagrams at 2,048 bytes by default. A record with long paths and many background tasks must still be delivered, if necessary without `background_tasks`, never silently dropped. Missing `background_tasks` must not be read as "all tasks finished." *Tests: Task 4, `large_record_is_delivered`; Task 5, `missing_background_tasks_skips_reconciliation`.*
4. **Unknown or garbage input.** An unknown hook event name, a payload that isn't JSON, or a garbage datagram must be ignored, and the service must keep processing. *Tests: Task 4, `unknown_event_is_rejected`; Task 8, `garbage_datagram_is_ignored`.*
5. **Stale socket after a crash, or a second instance.** `cusco serve` must replace a socket file left behind by a crash, but must refuse to start when another instance is answering. *Test: Task 8, `stale_socket_is_replaced_and_second_serve_refused`.*

### Task 1: Crate, node tree and derived state

**Files:**
- Create: `Cargo.toml`, `.gitignore` (`/target`), `src/lib.rs`, `src/tree.rs`
- Test: `tests/tree.rs`, `tests/common/mod.rs`

**Interfaces:**
- Produces (in `cusco::tree`):
  - `pub type Millis = u64;` `pub const STALE_AFTER: Millis = 3_600_000;`
  - `pub type Attrs = serde_json::Map<String, serde_json::Value>;`
  - `pub enum Kind { Machine, Client, Process, Session, Turn, Agent, Request }`, serialized snake_case
  - `pub enum State { NeedsInput, Working, Unknown, Idle }`, serialized snake_case
  - `pub enum Outcome { Ok, Error, Cancelled }`, serialized lowercase
  - `pub enum Event { Open { id: String, attrs: Attrs }, Close { id: String, outcome: Outcome }, Attr { id: String, attrs: Attrs }, Lost { scope: String }, Sync { scope: String, nodes: Vec<(String, Attrs)> } }`
  - `#[derive(Clone, Copy, Debug)] pub struct Client { pub name: &'static str, pub observes: &'static [&'static str] }`
  - `pub fn kind_of(id: &str) -> Option<Kind>`
  - `impl Tree { pub fn new(clients: &[Client], stale_after: Millis, at: Millis) -> Tree; pub fn apply(&mut self, event: Event, at: Millis); pub fn state(&self, id: &str) -> Option<State>; pub fn cause(&self, id: &str) -> Option<String>; pub fn contains(&self, id: &str) -> bool; pub fn attrs(&self, id: &str) -> Option<&Attrs> }`
- Produces (in `tests/common/mod.rs`): `pub const CLAUDE: Client`, `pub fn tree() -> Tree`, `pub fn open(t: &mut Tree, id: &str, at: Millis)`, `pub fn open_with(t: &mut Tree, id: &str, attrs: serde_json::Value, at: Millis)`, `pub fn close(t: &mut Tree, id: &str, outcome: Outcome, at: Millis)`

**Path grammar.** `/` is the machine. `/<client>` is a client created by `Tree::new`. Every deeper segment is `kind:id`. Allowed parent → child kinds: client → process, session; session → turn; turn → agent, request; agent → agent, request. `kind_of` returns `None` for anything else, and `apply` ignores events whose id doesn't parse.

**Semantics** (from the design's Data model section):
- `Open` is an idempotent upsert. It merges attrs, marks the node open and confirmed, and creates missing ancestors implicitly.
- `Attr` merges attrs into an existing node and confirms it. On an unknown id it is ignored; only `Open` creates nodes.
- `Close` on an unknown id is ignored. Closing a node closes its open request children. Closing a session closes everything beneath it. Closing a turn leaves its agents open.
- After every `apply`, closed nodes with no open descendant are removed. Machine and client nodes are never removed.
- State is `needs_input`, then `working`, then `unknown`, then `idle`, in that order, computed from confirmed and unconfirmed open nodes in the subtree, the node included.
- `cause` is the responsible node of the deciding category: the deepest one, then the earliest opened, then the lowest id. It returns `None` when the state is `idle`.

### Task 2: Confirmation, staleness, process nodes, `Lost` and `Sync`

**Files:**
- Modify: `src/tree.rs`
- Test: `tests/confirmation.rs`

**Interfaces:**
- Consumes: Task 1's `Tree`, `Event` and helpers.
- Produces: `impl Tree { pub fn expire(&mut self, at: Millis); pub fn next_deadline(&self) -> Option<Millis>; pub fn process_exited(&mut self, pid: u32, at: Millis) -> Vec<String> }`. `process_exited` returns the ids of the sessions it closed.

**Semantics** (from the design's Recovery section):
- A `process` node is always unconfirmed.
- Opening or updating a session whose attrs contain `"pid": P` removes `/<client>/process:P`.
- Any event naming a node confirms it and its ancestors.
- `expire(at)` unconfirms open turn, agent and request nodes whose `last_confirmed + stale_after <= at`. Sessions with nothing open never go stale.
- `next_deadline` is the earliest such expiry among open, confirmed work and request nodes.
- `Lost { scope }` unconfirms every open node in the scope.
- `Sync { scope, nodes }` replaces the subtree under `scope` with exactly `nodes`, all open and confirmed. `scope` itself is kept.

### Task 3: Rows and change publication

**Files:**
- Create: `src/row.rs`
- Modify: `src/lib.rs`
- Test: `tests/rows.rs`

**Interfaces:**
- Consumes: Tasks 1–2.
- Produces (in `cusco::row`):
  - `#[derive(Serialize, Clone, Debug, PartialEq)] pub struct Row { pub id: String, pub kind: Kind, pub state: State, pub since: Millis, pub reason: Option<String>, pub cause: Option<String>, pub counts: Option<Counts>, pub attrs: Attrs }`. It serializes `since` as RFC 3339, and omits `reason`, `cause` and `counts` when they're `None`.
  - `#[derive(Serialize, Clone, Debug, PartialEq, Default)] pub struct Counts { pub sessions: u32, pub needs_input: u32, pub working: u32, pub unknown: u32, pub idle: u32 }`
  - `pub enum Change { Upsert(Row), Remove(String) }`
  - `impl Tree { pub fn rows(&self) -> Vec<Row>; pub fn take_changes(&mut self) -> Vec<Change> }`, both sorted by id.

**Row rules** (from the design's Rows section):
- `since` is when the node's state last changed.
- `reason` is the cause's `attrs.reason` and appears only when the state is `needs_input`.
- `cause` is `None` when the state is `idle`.
- `counts` appears on machine and client rows only: the open sessions beneath the row, in total and by state.
- Client rows carry `attrs.observes` from their `Client`.
- When a turn closes, its session's attrs get `last_turn: {"outcome", "ended_at"}`.
- `take_changes` diffs the current rows against the rows it returned last time. It emits `Upsert` for new or changed rows and `Remove` for vanished ones.

  - `pub fn tool_digest(tool_name: &str, tool_input: &serde_json::Value) -> String`: SHA-256 over `tool_name`, a newline, then `serde_json::to_string(tool_input)`. Returns the first 16 bytes as 32 lowercase hex characters.
- Produces (in `cusco::hook`): `pub fn send_record(dir: &Path, record: &HookRecord) -> std::io::Result<()>` and `pub fn run_hook(client: &str, input: impl Read, dir: &Path)`.

**Field mapping in `from_payload`:**
- `hook_event_name` → `event`, `session_id` → `session_id`.
- `prompt_id` (Claude) or `turn_id` (Codex) → `turn_id`.
- These fields map by the same name: `agent_id`, `agent_type`, `tool_use_id`, `tool_name`, `notification_type`, `source`, `elicitation_id`, `cwd`, `transcript_path`.
- `error` (`StopFailure`) → `error`.
- `background_tasks[].{id, type, status}` → `background_tasks`.
- `tool_input` produces `digest` and is never stored.
- `client` must be `claude` or `codex`.
- `event` must be in that client's event list, or the result is `UnknownEvent`.
- Every id-valued field must be non-empty, at most `MAX_ID_BYTES`, and free of `/`, or the result is `InvalidId(field)`.

**`find_ancestor` and `surface`:**
- `find_ancestor` walks parent pids from `start`. It matches when the executable's file name equals `executable`, or when `executable` contains `/` and the full path equals it.
- `surface` returns `desktop` if the client process's executable path contains `/Library/Application Support/Claude/` or `/app-server-daemon/`, and `cli` otherwise.

**`run_hook`:**
1. Read stdin, capped at 1 MiB, and parse it as JSON.
2. Build the record and set `pid` and `surface` from `find_ancestor(getpid, client)`.
3. If `CUSCO_RECORD` is set, append the record as one JSON line to that file.
4. Call `send_record`.
5. Every error is swallowed. Nothing is ever written to stdout.

**`send_record`:**
- Creates an unbound `UnixDatagram`, sets non-blocking mode, and raises `SO_SNDBUF` to 65536 with `libc::setsockopt`.
- Sends to `dir/ingest.sock`.
- On `EMSGSIZE`, it clears `background_tasks` and sends once more.

### Task 8: The service

**Files:**
- Create: `src/server.rs`
- Modify: `src/lib.rs`
- Test: `tests/server.rs`

**Interfaces:**
- Consumes: everything above.
- Produces (in `cusco::server`):
  - `pub const INGEST_SOCKET: &str = "ingest.sock"; pub const API_SOCKET: &str = "api.sock"; pub const SUBSCRIBER_QUEUE: usize = 256;`
  - `pub fn default_dir() -> PathBuf`
  - `pub struct Config { pub dir: PathBuf, pub stale_after: Millis, pub subscriber_queue: usize, pub executables: Vec<(&'static str, String)> }`. Task 9 uses `executables`; an empty list disables process scanning.
  - `pub fn serve(config: Config) -> std::io::Result<Server>`, `impl Server { pub fn shutdown(self); pub fn wait(self) }`

**Threads and core loop:**
- `serve` creates `dir` with mode 0700.
- If `api.sock` exists and accepts a connection, `serve` returns `ErrorKind::AddrInUse`. Otherwise it removes stale socket files and binds both sockets, with `SO_RCVBUF` raised to 262144 on the ingest socket.
- An ingest thread receives into a 1 MiB buffer. It parses each datagram as a `HookRecord` and drops anything unparseable.
- An accept thread spawns one thread per connection. That thread reads one request line, sends it to the core, then writes every line from its receiver followed by `\n`.
- The core thread owns `Tree`, one adapter per client (`ClaudeAdapter`, `CodexAdapter`), `Subscribers` and `rev`. Its loop:
  1. Call `recv_timeout(next_deadline - now)` on its channel.
  2. Apply the input.
  3. Call `tree.expire(now)`.
  4. For each change from `take_changes()`, increment `rev` and publish `(rev, change)`.
- For `get`, the core sends the snapshot line on a one-shot channel and drops it.
- For a request that fails to parse, the core sends `error_line` and drops the channel.
- `shutdown` stops the threads and removes both socket files before returning.

### Task 9: Process liveness

**Files:**
- Modify: `src/process.rs`, `src/server.rs`
- Test: `tests/liveness.rs`

**Interfaces:**
- Consumes: `Config.executables` (Task 8) and `Tree::process_exited` (Task 2).
- Produces (in `cusco::process`):
  - `pub fn list_processes(executables: &[(&'static str, String)]) -> Vec<(&'static str, u32)>`, using `libc::proc_listallpids` and the same matching rule as `find_ancestor`
  - `pub fn watch_exit(pid: u32, on_exit: impl FnOnce() + Send + 'static)`. It spawns a thread, registers `EVFILT_PROC` with `NOTE_EXIT` on a new `kqueue`, blocks in `kevent`, then calls `on_exit`. If registration fails with `ESRCH`, it calls `on_exit` immediately.

**Server changes:**
- At startup, for each listed process, apply `Open` for `/<client>/process:<pid>` and watch its exit.
- When the core first sees a session `pid` it isn't watching, it watches that pid too.
- On exit, call `tree.process_exited(pid)`. For each closed session, call that client's adapter `forget_session` with the session id, then remove `/<client>/process:<pid>`.
